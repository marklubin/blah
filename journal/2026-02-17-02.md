# Session Journal - 2026-02-17-02

## Summary
Implemented the Discord backend in the MCP router and rewrote blah's Discord adapter as a thin proxy to the router. The router now handles all Discord API interaction (token management, REST API calls, message normalization), and blah's adapter simply makes HTTP calls to localhost:8080/discord/*.

## Decisions Made
- Followed existing `notifications.py` pattern for MCP tools + HTTP routes in the same file
- Followed `todoist.py` pattern for the async `_discord_api()` helper (returns `(data, error)` tuple)
- Token management (`set_token`, `extract_token`) is MCP-only — no HTTP routes needed since those are interactive operations
- `extract_token()` reuses existing Discord tabs when available, only opens new ones if needed
- Auth exempt prefix `/discord/` added to router middleware since it's Tailscale-protected like other HTTP APIs
