## Summary
Implemented Phase 3: Publishing + Bluesky Adapter. Built the PlatformAdapter ABC, BlueskyAdapter (atproto SDK), PublishService, and implemented all remaining rant CLI commands (publish, delete, failures, retry, mark-posted) plus context show/edit. 19 new tests added (67 total), all passing.

## Decisions Made
- PlatformAdapter ABC is synchronous with post/delete_post/get_post/post_thread — thread support via default chained post() implementation
- PostContent and PostResult dataclasses keep the adapter interface clean — adapters don't need to know about DB models
- BlueskyAdapter builds reply references by fetching the parent post and checking if it's already a reply (to get the correct root ref)
- PublishService handles the piece status lifecycle: approved → publishing → published/failed
- Rant auto-completes when all non-draft pieces are published/failed
- publish_piece() accepts both "approved" and "failed" status (for retry)
- _get_adapters() in CLI builds adapters from settings — lazy authentication at publish time only
- context edit uses $EDITOR/$VISUAL/vi fallback chain
- No DB migration needed — schema already had all required columns (external_id, external_url, published_at, error, retry_count)
