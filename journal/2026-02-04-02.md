## Decisions Made
- Chat loop lives in BaseAgent.run_chat() rather than a separate chat.py — cleaner since the loop is tightly coupled to the agent's tool execution
- Tool registration uses a two-layer approach: @tool decorator attaches metadata, collect_tools() scans objects to build ToolDef instances, ToolRegistry holds them
- RantAgent creates external RantTools and ContextTools objects, then registers their tools — keeps tool logic separate from agent logic
- MockLLMClient uses a simple queue of scripted responses — add_response() for text and/or tool_use, chat() returns next in queue
- Rich Markdown rendering for assistant messages in the chat loop
- Square brackets in Rich console output need care — platform names like [bluesky] get interpreted as markup tags
