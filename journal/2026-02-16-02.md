# Session Journal - 2026-02-16-02

## Summary
Implemented a general-purpose notification queue as a new MCP router backend. Services (blah radar, lab, future projects) can push notifications via MCP tools or HTTP POST, and any client can read them via MCP tools or HTTP GET. Storage is SQLite at `~/notifications.db`. Also wired the blah radar pipeline to push best-effort notifications on report completion and polling failures.

## Decisions Made
- Named the MCP tool function `list_notifications` instead of `list` to avoid shadowing Python's built-in `list` type (which broke `list[str]` annotations). The MCP tool name remains `list` via `@mcp.tool(name="list")`.
- Used 8-char truncated UUIDs for notification IDs, matching the lab backend pattern.
- Notifications from the pipeline are best-effort (fail silently) — they should never block or break the radar flow.
- Used `httpx.post` with a 2-second timeout for pipeline notifications, since the pipeline is synchronous code.
