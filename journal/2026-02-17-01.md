# Session Journal - 2026-02-17-01

## Summary
Implemented the Discord adapter using raw httpx with user token authentication, replacing the browser-scraping approach. Discord now works like Bluesky/Reddit/Twitter — polled automatically via API during `blah radar pull`. The adapter uses Discord's REST API directly with the user token as the Authorization header, avoiding the async complexity of `discord.py-self` and keeping everything synchronous.

## Decisions Made
- **Raw httpx over discord.py-self**: Used raw httpx REST calls instead of the library, avoiding async complexity and an extra dependency. httpx was already a project dependency.
- **User token auth**: Token stored in config.yaml, validated via `/users/@me` on each startup. No refresh logic needed — token persists until password change.
- **Guild discovery via `/users/@me/guilds`**: Works for user tokens (unlike `/guilds` which is bot-only).
- **Channel source type**: Added `channel` as a new source type in the pipeline, alongside `account`, `timeline`, `search`, `subreddit`, etc.
- **DiscordTools now takes adapter**: Changed constructor from `DiscordTools(db)` to `DiscordTools(db, adapter=None)` so it can call adapter methods for server/channel listing.
